Una app de pronósticos del Mundial 2026 construida sin servidores propios, sin proceso de compilación, desplegable en minutos — y que funciona sin internet una vez instalada.

🏆 Para entender el contexto

¿Qué hace MundialBet?

Permite a grupos de amigos competir pronosticando resultados del Mundial de Fútbol 2026. Cada jugador empieza con 90.000 puntos virtuales y apuesta en cada partido. Un motor automático liquida las apuestas apenas termina cada juego.

👤 El jugador hace...
  • Ingresa con su cuenta Google
  • Elige un equipo favorito del Mundial
  • Apuesta puntos en partidos (1-X-2)
  • Sigue el ranking en tiempo real
  • Recibe notificaciones de resultados
  • Comparte álbum de figuritas digitales
🤖 La app hace sola...
  • Actualiza marcadores cada 5 minutos
  • Liquida apuestas automáticamente
  • Calcula y paga bonos por precisión
  • Genera cuotas (sin fuente externa)
  • Envía notificaciones push masivas
  • Se actualiza sin reinstalar (SW)
🛡️ El administrador puede...
  • Ver todos los usuarios y saldos
  • Ajustar cuotas manualmente
  • Cerrar o abrir grupos
  • Activar el cierre de fase de grupos
  • Lanzar notificaciones push globales
  • Ver panel de diagnóstico en vivo

Firebase — El backend en la nube
Auth · Firestore · Cloud Messaging · Hosting · Sin servidor propio
BaaS ▼
🧑 Para no técnicos

Firebase es el "servidor" de la app, pero sin que nosotros tengamos que administrar ningún servidor. Google lo gestiona todo. Cuando un usuario apuesta, ese dato se guarda en la nube de Firebase y al instante aparece en el celular de todos sus compañeros de grupo — sin recargar la página.

⚙️ Para técnicos

Firebase JS SDK v10 (modo compat) cargado via <script> desde gstatic.com. Auth con persistencia LOCAL (IndexedDB). Firestore con listeners en tiempo real (onSnapshot) y reintentos automáticos. FCM para push web/PWA. Hosting como CDN con SPA rewrite (** → /index.html). El estado de auth se expone via window.MBFirebase.onAuth(cb).

Agente automático — El motor de resultados
Node.js · GitHub Actions cron · football-data.org · Firebase Admin SDK
Backend ▼
🧑 Para no técnicos

Cada 5 minutos, GitHub ejecuta automáticamente un pequeño programa robot. Este robot consulta una API de resultados de fútbol, detecta si algún partido terminó, y si es así: paga las apuestas ganadas, actualiza los saldos de cada jugador y envía una notificación a todos los teléfonos. Funciona aunque el creador de la app esté dormido.

⚙️ Para técnicos

Script Node.js 20 que corre en GitHub Actions con cron */5 * * * *. Usa Firebase Admin SDK con Service Account para escribir en Firestore con privilegios. Consulta football-data.org v4 (plan gratis, competición WC). Las cuotas se generan algorítmicamente (modelo de ranking), no se depende de ninguna fuente externa de odds. Soporta modo BONUS_DRY_RUN=1 para simular sin escribir.

🔄 Cómo fluyen los datos

Los 5 flujos principales

Desde que el usuario abre la app hasta que recibe la notificación de un resultado, estos son los caminos que recorre la información.

1
Apertura de la app y login automático
Splash → React mount → Firebase.onAuth() → Usuario logueado ✓ → Splash oculto
El splash espera el evento mb-auth-ready antes de ocultarse → el usuario nunca ve el estado "no logueado"
2
El usuario hace una apuesta
UI apuesta → MB.placeBet() → Firestore: bets/{uid_matchId} → Firestore: users/{uid}.saldo -= → onSnapshot actualiza UI
Transacción atómica: el saldo se descuenta y la apuesta se registra en la misma operación
3
Liquidación automática de un partido
GitHub Actions cron → football-data.org API → Partido FINISHED → Firestore: bets settled → users.saldo += payout → FCM push 🔔
Si un jugador apostó 5.000 puntos a cuota 2.1 y ganó → recibe 10.500 puntos automáticamente
4
Ranking en tiempo real
Firestore.onSnapshot(users) → sort por saldo desc → Render ranking UI
Cada cambio en Firestore (saldo de cualquier jugador) dispara automáticamente el re-render del ranking para todos
5
Actualización de la app (Service Worker)
Dev sube cambio a GitHub → GitHub Actions deploy → SW detecta CACHE nuevo → controllerchange → window.reload() automático
Los usuarios siempre tienen la versión más nueva. Sin App Store, sin reinstalar, sin intervención del usuario

Términos para entender la arquitectura

Si algo en este documento no quedó claro, aquí están las definiciones simples de los términos técnicos más usados.

PWA (Progressive Web App)
Una página web que se puede "instalar" en el teléfono o computador como si fuera una app normal, funciona sin internet y recibe notificaciones push.
Service Worker
Un programa que vive en el navegador en segundo plano. Guarda una copia de la app y la sirve cuando no hay internet. También detecta versiones nuevas.
sw.js
Firebase
Plataforma de Google que provee base de datos, login de usuarios, notificaciones y hosting, todo sin que tengamos que administrar ningún servidor.
Firestore
La base de datos de Firebase. Guarda datos en "colecciones" (como carpetas) y "documentos" (como archivos). Cuando algo cambia, todos los dispositivos conectados se actualizan al instante.
React
Librería de JavaScript para construir interfaces de usuario. Permite que la pantalla se actualice automáticamente cuando cambian los datos, sin recargar la página.
JSX
Una extensión de JavaScript que permite escribir código que parece HTML dentro de un archivo JS. El navegador no lo entiende solo — Babel lo transforma primero.
*.jsx
GitHub Actions
Sistema de automatización de GitHub. Permite ejecutar programas automáticamente cuando alguien sube código, a cierta hora, o manualmente.
.github/workflows/
BaaS (Backend as a Service)
Un "backend en la nube" listo para usar. En vez de programar un servidor propio, usas servicios de terceros (como Firebase) que ya hacen todo eso.
CDN (Content Delivery Network)
Red de servidores distribuidos por el mundo. Sirve los archivos de la app desde el servidor más cercano al usuario, haciendo que cargue más rápido.
onSnapshot
Función de Firestore que "escucha" una colección en tiempo real. Cada vez que un dato cambia en la base de datos, esta función avisa automáticamente a la app.
FCM (Firebase Cloud Messaging)
Sistema de Google para enviar notificaciones push a teléfonos y navegadores. Funciona aunque la app esté cerrada.
NoSQL
Tipo de base de datos que no usa tablas tradicionales (como Excel). Firestore usa documentos JSON anidados, más flexibles para datos que cambian de forma.
